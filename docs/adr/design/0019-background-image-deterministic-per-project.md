# 배경 이미지 선택을 프로젝트 단위로 결정론화한다

Date: 2026-06-16

## Status

Accepted

## Context

타이틀·클로징 슬라이드는 명시 배경이 없을 때 테마(다크/라이트)별 기본 배경 이미지를 자동 주입한다 (design/0016). 그 이미지는 테마 폴더에 여러 장이 있고, 현재 그중 하나를 **무작위로** 고른다. 같은 export 한 번 안에서는 캐시로 동일 이미지를 보장하지만, 캐시는 export 시작 시점에 매번 비워진다.

이 구조에서 두 가지 비일관성이 드러났다.

- **재export 때마다 배경이 바뀐다.** 슬라이드를 부분 수정하고 다시 내보내면 무작위 선택이 새로 일어나, 직전 산출물과 타이틀·클로징 배경이 달라진다. 사용자가 보기엔 "고치지도 않은 표지 배경이 매번 바뀐다".
- **미리보기(HTML)와 최종본(PPTX)의 배경이 다르다.** 두 export 경로가 각각 캐시를 비우고 각자 무작위로 고르므로, 같은 프로젝트인데 미리보기에서 본 배경과 PPTX 배경이 일치하지 않는다.

근본 원인은 배경 선택이 **프로젝트에 고정·영속되지 않은 무작위**라는 것이다. design/0016 은 "배경을 켤지/끌지"(정책)는 DESIGN.md 로 결정론화했지만, "켰을 때 어떤 이미지인지"는 매 호출 무작위로 남겨 두었다. design/0015 의 "같은 디자인 의도면 같은 결과" 원칙이 배경 이미지 선택에는 닿지 않은 사각지대다.

## Decision Drivers

- 같은 프로젝트는 몇 번을 export 하든, 어느 경로(HTML/PPTX)로 내보내든 타이틀·클로징이 **같은 배경**을 써야 한다.
- 타이틀과 클로징은 한 덱 안에서 서로 **같은 배경**을 공유해야 한다 (한 벌의 표지·마무리).
- 배경에 다양성은 유지하고 싶다 — 모든 프로젝트가 같은 한 장으로 고정되면 단조롭다. 프로젝트마다 다르되, 한 프로젝트 안에서는 안정적이어야 한다.
- design/0016 의 정책(끄기/켜기)과 명시 배경 우선순위를 깨지 않아야 한다.

## Decision

**배경 이미지 선택을 프로젝트 단위로 한 번 결정하고 영속화한다.** 무작위는 "프로젝트가 처음 배경을 고를 때" 한 번만 일어나고, 그 선택은 프로젝트에 저장돼 이후 모든 export 가 같은 이미지를 재사용한다.

- 선택 기준은 프로젝트에 안정적으로 묶인 값(프로젝트 식별자)에서 결정론적으로 파생한다 — 별도 영속 저장 없이 (식별자, 테마) 조합을 해시해 이미지 인덱스를 정한다. 같은 프로젝트는 항상 같은 이미지, 프로젝트마다 식별자가 달라 다른 이미지가 된다. (영속 저장 대안 대비 새 저장 키·편집 동작 정의가 불필요해 단순하다.)
- HTML 과 PPTX 두 export 경로는 이 영속된 선택을 함께 읽는다 — 더 이상 각자 무작위로 고르지 않는다. 미리보기와 최종본의 배경이 일치한다.
- 타이틀·클로징은 같은 프로젝트 선택값을 공유하므로 한 덱 안에서 동일 배경이 된다.
- 프로젝트 간 다양성은 "프로젝트마다 선택값이 다름"으로 유지된다. 전역 단일 고정이 아니다.

design/0016 의 정책 게이트(`none` 이면 자동 주입 생략)와 명시 배경(임포트 라운드트립 등) 우선순위는 그대로다 — 본 ADR 은 "자동 주입이 일어날 때 어떤 이미지인가"만 결정론화한다.

## 대안 검토

| 대안 | 설명 | 채택하지 않은 이유 |
|---|---|---|
| 현행 유지 (매 export 무작위) | export 시작마다 캐시 비우고 무작위 | 재export·경로마다 배경이 바뀌는 현재 버그 그대로 |
| 테마당 한 장으로 고정 | 무작위를 없애고 테마별 대표 이미지 1장만 사용 | 결정론적이지만 모든 프로젝트가 동일 배경 — 다양성 상실 |
| 프로세스 세션 캐시 수명 연장 | export 시작마다 캐시를 비우는 동작을 줄여 한 세션 내 일관성 확대 | 세션은 프로젝트와 무관하게 살고 죽음. 서버 재시작·다중 프로젝트에서 여전히 비결정적이고, 미리보기/최종본 경로가 다른 세션이면 또 어긋남 |
| **프로젝트 단위 결정론화 + 영속** | 최초 1회 선택을 프로젝트에 고정 | **채택** — 같은 프로젝트 안정성과 프로젝트 간 다양성을 동시에 만족, 경로 간 일치 보장 |

## Consequences

### Positive

- 같은 프로젝트는 재export·경로와 무관하게 타이틀·클로징 배경이 항상 동일하다.
- HTML 미리보기와 PPTX 최종본의 배경이 일치한다.
- 프로젝트 간 배경 다양성은 유지된다.
- design/0015·0016 의 "디자인 의도는 결정론적으로 프로젝트에 묶인다" 원칙이 배경 이미지까지 확장된다.

### Negative / Risks

- 식별자 파생 방식이므로, 식별자가 바뀌는 마이그레이션(프로젝트 복제·재발급)에서는 배경이 달라질 수 있다 — 식별자가 안정적인 한 배경도 안정적이다.
- 테마 폴더의 이미지 파일 목록이 바뀌면(추가/삭제) 해시 → 인덱스 매핑이 흔들려 기존 프로젝트의 배경이 한 번 달라질 수 있다. 파일 순서 의존을 줄이려 정렬 후 인덱싱하지만, 목록 자체의 변화는 흡수하지 못한다.
- 선택은 식별자에 묶이므로, 사람이 "이 프로젝트만 다른 배경"을 원하면 현재는 식별자 외 우회로가 없다 (명시 배경 지정은 design/0016 경로로 가능).

### 검증으로 확인된 사항

- 같은 시드(프로젝트)는 export 사이 캐시가 비워져도 동일 이미지를 고른다 — 재export 일관성 확인.
- 시드를 바꿔 끼웠다 되돌려도 같은 시드는 항상 같은 결과 — 무작위가 아닌 결정론임을 확인.
- 여러 시드를 돌리면 두 종류 이상의 이미지가 나와 프로젝트 간 다양성이 유지됨을 확인.
- 시드를 None 으로 해제하면 레거시 무작위 모드로 안전하게 복귀 (하위 호환).
- HTML·PPTX·생성·수정 네 진입점 모두 같은 시드(프로젝트 식별자)를 걸어, 미리보기와 최종본 배경이 일치한다.
