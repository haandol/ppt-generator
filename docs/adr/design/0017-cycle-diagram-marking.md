# 순환 다이어그램 마킹 + 화살표 방향 규칙

Date: 2026-06-15

## Status

Accepted (2026-06-15)

## Context

순환(cycle) 구조 다이어그램에서 LLM 이 화살표의 의미적 방향을 반대로 생성하는 결함이 관찰됐다(ReAct 루프의 왼쪽 절반이 거꾸로). 조사 결과 근본 원인은 무작위 실수가 아니라 **생성 프롬프트의 구조적 공백**이었다:

- 다이어그램 화살표 좌표 가이드가 좌→우 파이프라인과 fan-out/fan-in bus 패턴만 다루고, **순환·복귀(loop / back-edge) 화살표의 방향 규칙·예시가 전혀 없다**.
- 프롬프트가 "모든 다이어그램 화살표는 끝점에 화살촉(end_arrow)"이라고 단정한다. 모든 예시가 좌→우·상→하(작은 좌표가 출발점)이므로, 출발 노드가 큰 좌표 쪽에 있는 복귀 화살표에서 LLM 이 시작/끝을 흐름과 맞추지 못해 방향이 뒤집힌다.

또한 이 결함을 lint 로 잡으려면(lint/0006) lint 가 "이 묶음이 순환 다이어그램"임을 알아야 하는데, 좌표만으로 사이클 여부를 추측하면 false positive 가 크다. 따라서 디자인 스펙이 순환임을 **명시 선언**해야 lint 가 추측 없이 검증할 수 있다.

즉 두 가지가 함께 필요하다: (1) LLM 이 순환 화살표를 올바른 방향으로 그리도록 하는 생성 측 규칙, (2) 그 다이어그램이 순환임을 스펙에 남겨 검증 측(lint)이 신뢰할 수 있게 하는 마킹.

## Decision Drivers

- 순환 화살표 방향 오류를 생성 단계에서 줄이고 싶다 (근본 원인이 프롬프트 공백).
- lint(lint/0006)가 사이클을 추측하지 않도록, 순환 여부를 스펙에 결정론적으로 선언해야 한다.
- 마킹은 가벼워야 한다 — 모든 화살표에 출발/도착을 다는 침습적 방식은 피한다.
- 기존 의미 트리(레이아웃 노드의 role 라벨, design/0011)와 정합해야 한다.

## Decision

**순환 다이어그램을 디자인 스펙의 의미 트리에서 명시 마킹하고, 생성 프롬프트에 순환/복귀 화살표의 방향 규칙과 예시를 추가한다.**

### 1. 순환 마킹

레이아웃 의미 트리의 다이어그램 묶음 노드에 **"순환 다이어그램"임을 나타내는 마킹**을 둔다. 마킹은 기존 노드의 의미 라벨 체계(role) 위에 얹는 가벼운 관례로 하며, 별도의 라인별 출발/도착 필드는 두지 않는다. 마킹된 묶음의 자식 노드(사이클 참여 노드)와 그 사이를 잇는 화살표가 lint/0006 의 위상 검증 입력이 된다.

노드↔화살표 연결은 화살표 끝점이 닿는 노드의 bbox 로 판정한다(기존 좌표 부착 메커니즘 재사용). 한 끝점이 여러 노드 코너에 동시 근접해 모호한 경우는 lint 가 위반으로 단정하지 않고 검사를 건너뛴다(보수적).

### 2. 화살표 방향 규칙 (프롬프트)

생성 프롬프트의 다이어그램 화살표 가이드에 순환/복귀 화살표 규칙을 추가한다:

- 화살촉(흐름의 도착점 표시)은 **흐름상 다음 노드(target)** 에 위치한다.
- 복귀(back-edge) 화살표는 좌표가 큰→작은 방향이어도 무방하다. "출발점이 항상 작은 좌표"라는 암묵 가정을 제거한다.
- 3노드 삼각 순환(예: ReAct Think→Act→Observe→Think)의 좌표 예시를 명시해, 각 화살표가 출발 노드 변에서 시작해 도착 노드 변에서 끝나도록 안내한다.

이 규칙은 결정론적 보장이 아니라 LLM 의 방향 정확도를 높이는 1차 방어선이며, 위상 검증 lint(lint/0006)가 2차 안전망이 된다.

## 대안 검토

| 대안 | 설명 | 채택하지 않은 이유 |
|---|---|---|
| 프롬프트 규칙만 추가 | 순환 화살표 방향 규칙·예시만 보강, 마킹 없음 | LLM 준수에 100% 의존, lint 안전망이 사이클을 추측해야 해 false positive |
| 라인별 source/target 의미 필드 | 모든 화살표에 출발/도착 노드 명시 | 가장 견고하나 schema·export·parser·다수 lint 파급 — 과도 |
| 노드별 순서 번호(sequence) 부여 | 각 노드에 흐름 순번을 매김 | 순환은 시작/끝이 없어 순번이 모호. 분기·합류 다이어그램엔 부적합 |
| **순환 묶음 마킹 + 프롬프트 방향 규칙** | 다이어그램 단위로 사이클 선언, 화살표는 좌표 부착으로 연결 판정 | **채택** — 가볍고, lint 추측 제거, 기존 트리와 정합 |

## Consequences

### Positive

- 순환 화살표 방향 오류가 생성 단계에서 줄어든다 (프롬프트가 근본 공백을 메움).
- 다이어그램 단위 마킹 하나로 lint/0006 의 위상 검증이 추측 없이 동작 — false positive 차단.
- 라인별 의미 필드 추가 없이 가벼우며, 기존 의미 트리·좌표 부착 메커니즘을 재사용한다.

### Negative / Risks

- 프롬프트 규칙은 LLM 준수에 의존하므로 방향 오류를 0 으로 만들지 못한다 (그래서 lint 안전망이 필요).
- LLM 이 순환 마킹을 누락하면 lint 검증이 비활성화된다 — 프롬프트가 순환 구조에 마킹을 붙이도록 유도해야 한다.
- 마킹을 기존 role 라벨 관례로 얹으면, 관례를 모르는 외부 편집/임포트 스펙에는 적용되지 않는다 (생성 경로 우선).
- 새 방향 규칙이 기존 좌→우 파이프라인·fan-out bus 패턴과 충돌하지 않도록 프롬프트 작성에 주의해야 한다.
