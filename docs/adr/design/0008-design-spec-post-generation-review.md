# Design Spec Post-Generation LLM Review

Date: 2026-04-02

## Status

Accepted (2026-09-09)

## Context

디자인 스펙 생성 시 LLM이 프롬프트 규칙(폰트 크기 하한, 카드 높이 균일성, 좌우 영역 일관성 등)을 위반하는 경우가 빈번하다. 특히 복잡한 레이아웃(two_column, arch_diagram 등)에서 공간이 부족하면 LLM이 임의로 폰트를 10pt까지 줄이거나, 수직 스택 카드 간 겹침/마진 불일치를 만드는 문제가 반복된다.

대응 방식의 경계:
- **프롬프트 규칙 강화**: 규칙을 추가해도 LLM이 무시하는 경우가 있음
- **서버 사이드 validation**: 하드코딩된 규칙은 edge case가 많고, 잘못된 자동 수정으로 레이아웃을 오히려 망칠 리스크가 큼
- **Visual QA**: 렌더링 후 픽셀 결함에는 적합하지만 사실 근거와 덱 전체 서사는 판단하지 않음

슬라이드 단위 검토만으로는 반복 주장, 용어 드리프트, agenda와 본문 불일치, 결론이
근거를 반영하는지, 발표 시간 대비 밀도가 적절한지를 판단할 수 없다. 디자인 스펙 JSON
단계와 덱 전체 의미 단계의 read-only 리뷰를 분리해야 한다.

## Decision Drivers

- 기계적 lint가 잡지 못하는 시각·의미 문제를 LLM이 검토할 수 있어야 한다.
- 덱 전체 리뷰는 슬라이드 간 관계와 근거·가정을 함께 볼 수 있어야 한다.
- review는 결과를 직접 변경하지 않고 수정 필요 범위를 분류해야 한다.
- 슬라이드별 호출을 전부 강제하지 않고 위험한 슬라이드에 집중할 수 있어야 한다.

## Decision

디자인 스펙 리뷰를 두 수준으로 제공한다. 리뷰 태스크 조립과 결과 검증은 서버가
prepare/ingest 쌍으로 소유하고, 리뷰 판단은 클라이언트 LLM이 수행한다.

### 핵심 설계

1. **슬라이드 리뷰**: 렌더링 없이 한 슬라이드 spec의 균형, 계층과 가독성 위험을
   감지한다. lint나 Visual QA가 우선순위를 올린 슬라이드에 선택적으로 실행한다.
2. **lint 힌트 전달**: 기계적 lint 결과를 리뷰 프롬프트에 힌트로 실어, LLM 판단이 결정론적 검사와 어긋나지 않게 한다.
3. **덱 리뷰**: 모든 아웃라인의 계획·근거·가정, 화면 문구와 발표자 노트, 실제
   요소 배치·관계와 DESIGN.md의 의도를 함께 검토한다. 발표 목적·청중·시간도
   전달한다. 원래 컴포넌트 힌트만으로 실제 구성의 반복을 판단하지 않는다.
4. **리포트 전용**: review ingest는 수정하지 않는다. 저위험 시각 이슈는 Visual QA로,
   콘텐츠·구조 이슈는 사용자 결정으로 보낸다.

### 덱 리뷰 계약

덱 리뷰는 다음 issue type을 사용한다.

- `unsupported_claim`: 근거 참조 없이 확정적으로 표현된 외부 사실·수치
- `narrative_gap`: 앞뒤 논리 연결이나 결론 근거가 누락됨
- `duplicate_content`: 같은 주장이 불필요하게 반복됨
- `terminology_drift`: 같은 개념이 다른 이름으로 표현됨
- `agenda_mismatch`: agenda가 실제 본문을 대표하지 못함
- `conclusion_mismatch`: closing이 본문의 근거·행동 요청과 맞지 않음
- `time_density`: 발표 시간에 비해 슬라이드 또는 내용 밀도가 과도하거나 부족함

동일한 실제 content 구성의 3장 연속 사용은 불필요한 반복인지 검토할 신호다.
비교나 단계별 설명을 돕는 유효한 반복은 허용하고, 새 정보와 설명 목적이 없는 반복만
`duplicate_content`로 보고한다. 서로 다른 힌트로 만든 같은 구성과 같은 힌트로 만든
서로 다른 구성을 구분한다. 검토는 보고 전용이며 콘텐츠를 자동 재작성하지 않는다.

출처 식별자가 존재한다는 사실은 그 출처가 주장을 입증한다는 뜻이 아니다.
검토 입력에 출처 내용이 없으면 지원 여부를 확인했다고 보고하지 않으며, 검증이
필요한 주장은 확인할 근거를 명시한다. 실제 화면에 드러난 가정과 확정 주장을
구분하고, 발표자 노트에 추가된 주장도 같은 기준으로 검토한다.

각 issue는 severity, 관련 슬라이드 번호 목록, 설명과 다음 행동을 포함한다.
high severity는 사실성, 핵심 논리 또는 사용자 약속을 바꾸는 문제다. medium은
중복·용어·밀도처럼 품질에 영향을 주지만 의미 보존 수정이 가능한 문제다.

### 리뷰 체크리스트

| 항목 | 기준 | Severity |
|------|------|----------|
| 폰트 크기 하한 | 카드 제목 < 18pt, 카드 본문 < 16pt, 섹션 라벨 < 14pt, 모든 텍스트 < 10pt | high |
| 좌우 폰트 일관성 | 동일 역할 텍스트의 좌우 영역 간 폰트 크기 차이 > 4pt | high |
| 수직 스택 겹침 | 인접 카드 간 gap < 0 (겹침) | high |
| 수직 스택 높이 균일 | 같은 열의 카드 height_px가 불균일 | medium |
| 수직 스택 간격 균일 | 같은 열의 카드 간 gap이 불균일 (최대-최소 > 4px) | medium |
| 좌우 bottom 정렬 | 좌우 영역의 bottom edge 차이 > 8px | medium |
| 요소 겹침 | 같은 레벨 요소 간 bounding box 겹침 | high |
| 동일 행 폰트 일관성 | 같은 행의 동급 요소에서 대응 텍스트의 폰트 크기가 다름 | high 또는 medium |
| 동일 행 패딩 일관성 | 같은 행의 동급 요소에서 내부 패딩이 다름 | medium |

균일성·정렬·밀도 기준은 같은 역할과 강조 수준의 요소에 적용한다. DESIGN.md나
슬라이드 의도에 명시된 비대칭, 전환을 위한 여백과 강조를 차이 자체만으로 결함으로
판정하지 않는다. 실제 잘림·충돌·가독성 결함은 의도와 함께 검토한다.

### 리뷰 결과 처리

- **이슈 없음**: 그대로 저장, HTML 렌더링 진행
- **슬라이드 high 시각 이슈**: Visual QA 또는 좁은 component patch 대상으로 전달
- **덱 high 의미 이슈**: 사용자에게 관련 슬라이드와 변경 선택지를 보고
- **medium only**: 완료를 막지 않고 결과에 요약

리뷰 프롬프트의 체크리스트 식별자와 응답 스키마의 식별자는 하나의 정식 집합으로
관리한다. 프롬프트가 요구하는 규칙은 모두 스키마가 표현할 수 있어야 한다.
`has_high_severity`는 LLM이 제공한 값을 신뢰하지 않고 검증된 issue 목록의 severity에서
서버가 계산한다.

단일 슬라이드 리뷰와 덱 리뷰는 판단에 사용한 명세와 디자인 의도가 준비 이후
변경되면 결과 수신을 거부하고 다시 검토하도록 안내한다.

rule별 허용 severity는 체크리스트의 정식 계약으로 스키마가 검증한다. 기계적 lint가
이미 감지한 이슈를 LLM이 반복하지 않도록 한 경우, ingest 결과는 prepare에서 검증한
lint 이슈와 LLM 이슈를 합쳐 최종 high 여부와 fix 피드백을 계산한다.

### Alternatives Considered

1. **서버 사이드 하드코딩 validation**: 의미·내러티브 판단을 정적 규칙으로 표현하기 어려워 제외.
2. **Visual QA로 통합**: 픽셀 결함과 사실·서사 검토의 입력과 수정 권한이 달라 제외.
3. **슬라이드 리뷰만 유지**: 슬라이드 간 중복과 논리 연결을 발견하지 못해 제외.

### Acceptance Criteria

- 슬라이드 단위 review는 위험 신호가 있는 슬라이드에 선택적으로 수행할 수 있음
- 전체 덱에 대해 한 번의 deck review prepare/ingest가 제공됨
- deck review가 정식 issue type, 관련 슬라이드와 severity를 검증함
- lint 결과가 리뷰 프롬프트에 힌트로 전달됨
- 실제 배치가 다른 덱은 검토 입력에서 구분되며, 힌트 이름만 다른 동일 구성도 비교 가능함
- 디자인 의도·발표 조건·출처와 가정·발표자 노트가 검토 준비 과정에서 보존됨
- 출처 내용이 없는 상태를 사실 검증 완료로 보고하지 않음

### Out of Scope

- 리뷰 후 콘텐츠 자동 수정
- Visual QA 대체 (목적이 다르므로 별도 유지)

## Consequences

### 긍정적

- 폰트 크기 위반, 겹침 등 반복적인 규칙 위반을 렌더링 전에 감지
- 덱 전체의 근거, 반복, 용어와 내러티브 문제를 한 번에 확인 가능
- 슬라이드 리뷰를 위험 대상에 집중해 호출 수를 줄일 수 있음
- Visual QA 실행 전에 명백한 결함을 제거하여 Visual QA 효율 향상

### 부정적

- 덱 전체 review를 위한 추가 LLM 호출 1회가 필요함
- 의미 review가 false positive를 반환하면 사용자에게 불필요한 변경 선택지가 노출될 수 있음
- 체크리스트와 응답 스키마의 변경은 함께 이뤄져야 하므로 계약 검증 유지 비용이
  추가된다.
