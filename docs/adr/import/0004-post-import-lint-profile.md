# 임포트 직후 소스 인식 Lint 프로필

Date: 2026-07-23

## Status

Accepted (2026-07-23)

## Context

외부 PPTX를 임포트한 결과도 생성 결과와 동일하게 텍스트 넘침, 캔버스 이탈, 깨진
기하처럼 기계적으로 감지 가능한 결함을 포함할 수 있다. 현재 lint는 생성·수정된 디자인
스펙을 중심으로 실행되며, 임포트 결과는 HTML 미리보기를 바로 생성하므로 변환 과정에서
생긴 결함이 사용자 육안 검수 전까지 드러나지 않는다.

기존 lint 전체를 임포트 직후 그대로 실행하는 방식은 적합하지 않다. 임포트된 슬라이드는
생성 슬라이드와 달리 그리드·의미 계층이 없을 수 있고, 작은 법적 고지, 카드 위 텍스트,
장식 요소처럼 원본이 의도한 구성을 그대로 보존해야 한다. 생성 계약을 전제로 한 규칙은
이들을 오류로 보고해 실제 충실도 결함보다 많은 오탐을 만든다.

HealthImaging 원본의 8페이지에서는 좌표·폰트·행간이 일치하지만 원본의 불렛 여백과
hanging indent가 보존되지 않아 가용 폭이 줄고, 2열 본문이 한 줄 더 감기면서 카드 아래로
넘쳤다. 기존 lint 전체 실행은 이 실제 결함을 놓치는 한편 생성 전용 규칙 위반을 여러 건
보고했다. 임포트 결과에 맞는 검사 범위와 수정 책임을 별도로 결정해야 한다.

## Decision Drivers

- 임포트 결과도 사용자에게 노출되기 전에 기계적으로 감지 가능한 렌더 결함을 보고해야 한다.
- 원본 보존이 우선이므로 생성 슬라이드의 구조·타이포그래피 정책을 강제하면 안 된다.
- lint의 역할은 감지와 리포트이며, 레이아웃을 자동 변경하지 않는 기존 원칙을 유지해야 한다.
- 구조 검사만으로 폰트 엔진 차이와 실제 줄바꿈을 완전히 예측할 수 없음을 인정해야 한다.
- 반복되는 변환 결함은 개별 슬라이드 보정보다 임포터·렌더러의 근본 원인 수정으로 해결해야 한다.

## Decision

PPTX 임포트 파이프라인에 **소스 인식 lint 단계**를 명시적으로 포함한다. 숨은 저장 훅으로
실행하지 않고, 임포트 변환이 끝난 디자인 스펙을 검사한 뒤 그 결과를 임포트 응답에 함께
노출한다.

lint는 입력 출처에 따라 규칙 프로필을 선택한다.

- 생성 결과는 기존 전체 정책과 계층 계약을 유지한다.
- 임포트 결과는 원본 충실도에 유효한 렌더 안전 규칙만 실행한다. 텍스트 넘침, 캔버스
  이탈, 비정상 크기처럼 원본과 무관하게 문제가 되는 항목은 검사한다.
- 그리드·의미 계층 존재, 생성 타이포그래피 최소값, 의도된 카드 중첩처럼 생성 계약이나
  스타일 선택을 전제로 하는 항목은 임포트 프로필에서 제외한다.

임포트 lint도 감지와 리포트만 수행한다. 자동으로 좌표, 글꼴, 박스 크기 또는 텍스트를
변경하지 않는다. 사용자는 보고된 슬라이드를 확인해 수정 여부를 결정한다. 여러 슬라이드에
반복되는 충실도 결함은 임포트 변환이나 양쪽 렌더 경로의 근본 원인을 수정하고 재임포트한다.
개별 콘텐츠 수정이 필요한 경우에만 기존 편집 흐름을 사용한다.

구조 검사 결과가 깨끗하더라도 줄바꿈·폰트 대체·클리핑처럼 렌더 엔진에 민감한 영역은
시각 QA 대상임을 응답에 구분해 표시한다. 원본과 픽셀 단위로 비교하는 검사는 상시 import
호출의 필수 단계가 아니라, 충실도 작업과 고위험 경고의 확인 단계로 둔다.

## Technical Details

- lint 실행 진입점은 입력 출처를 명시적으로 받아 규칙 프로필을 선택한다.
- 임포트 서비스는 변환·정규화 완료 후 저장과 HTML 렌더 전에 import 프로필을 실행한다.
- 임포트 응답은 기존 경고와 lint 결과를 구분 가능한 구조로 제공하되, 기존 호출자의 필수
  입력이나 prepare/ingest 계약은 변경하지 않는다.
- import 프로필의 규칙 목록은 허용 목록으로 관리해 새 생성 전용 규칙이 자동 유입되지
  않게 한다.
- 렌더 엔진 측정이 필요한 텍스트 넘침은 구조 lint 경고와 시각 QA 필요 상태를 구분한다.

## 대안 검토

| 대안 | 판단 |
|---|---|
| 임포트 후 기존 전체 lint를 그대로 실행 | 구현은 단순하지만 생성 전용 규칙의 오탐이 실제 결함을 가리므로 제외 |
| 저장 훅에서 lint를 암묵적으로 실행 | 모든 저장 경로를 덮지만 실행 시점과 응답 책임이 불명확해지고 테스트가 어려워 제외 |
| 임포트 후 자동으로 박스 확대·폰트 축소 | 원본 레이아웃을 훼손하고 근본 변환 버그를 숨기므로 제외 |
| 임포트 파이프라인에서 소스 인식 프로필로 감지·리포트 | 원본 보존과 조기 결함 발견을 함께 만족해 채택 |
| 모든 임포트에서 원본·HTML 픽셀 비교 강제 | 가장 직접적이나 외부 렌더러·폰트 의존성과 처리 시간이 커 상시 단계에서는 제외 |

## Consequences

### Positive

- 임포트 직후 실제 렌더 안전 결함을 사용자에게 일관된 형식으로 노출할 수 있다.
- 생성 전용 규칙의 오탐 없이 임포트 충실도 문제에 집중할 수 있다.
- 자동 보정이 원본을 훼손하거나 변환 버그를 숨기는 일을 방지한다.
- 반복 결함을 임포터·렌더러의 회귀 테스트와 근본 수정으로 연결할 수 있다.

### Negative / Risks

- 규칙마다 생성과 임포트 중 어느 출처에 적용되는지 분류·유지해야 한다.
- 구조 lint만으로 실제 브라우저·PowerPoint의 모든 텍스트 넘침을 검출할 수 없다.
- 임포트 응답의 경고량이 늘어나므로 실제 조치가 필요한 항목과 정보성 경고를 구분해야 한다.
- 시각 QA가 필요한 경고는 별도 렌더와 비교 시간이 든다.

## Acceptance Criteria

- PPTX 임포트 직후 import 전용 lint가 자동 실행되고 결과가 응답에 포함된다.
- import 프로필은 캔버스 이탈, 비정상 크기, 구조적으로 판정 가능한 텍스트 넘침을
  보고한다.
- import 프로필은 그리드·의미 계층, 생성용 최소 글자 크기, 원본의 의도된 중첩을
  위반으로 보고하지 않는다.
- lint는 임포트된 좌표, 크기, 글꼴, 텍스트를 자동 수정하지 않는다.
- 기존 임포트 호출자는 새 필수 인자 없이 동작하고 기존 경고를 계속 받을 수 있다.
- 규칙 프로필 선택, 응답 직렬화, 기존 호출 호환성을 검증하는 회귀 테스트가 존재한다.
- HealthImaging 8페이지처럼 브라우저 줄바꿈에 의존하는 결함은 lint 결과만으로 완료
  처리하지 않고 원본 대비 HTML·PPTX 시각 QA로 확인한다.
