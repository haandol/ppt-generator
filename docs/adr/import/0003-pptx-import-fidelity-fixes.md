# PPTX 임포트 충실도 개선 (autofit·stroke·chart·행간)

Date: 2026-07-22

## Status

Accepted

## Context

실제 배포용 PPTX(AWS HealthImaging 덱, 25슬라이드)를 임포트한 결과, 원본과 눈에 띄게
어긋나는 지점이 다수 발견됐다. 원본을 렌더한 이미지와 임포트 결과 스크린샷·디자인 스펙을
대조해 **네 가지 독립적 근본 원인**을 규명했다. 모두 [0001](0001-pptx-import-to-design-spec.md)이
표방한 "디자인 요소 최대 보존" 원칙을 코드가 지키지 못한 지점이다.

1. **텍스트 대폭 축소** — 타이틀/서브타이틀 등이 원본보다 훨씬 작게 렌더된다. 0001은
   "임포트 시 autofit 비활성화"를 결정했으나, autofit 모드 추출이 *OOXML autofit 태그가
   없는 경우*의 기본값을 잘못 잡아 축소 모드로 귀결됐다. OOXML 명세상 autofit 자식 요소가
   없으면 기본은 "축소 없음"이며, 이는 LLM 생성 슬라이드의 기본값(넘침 방지용 축소)과 반대다.

2. **그룹 내 라인아트 아이콘 실종** — 여러 슬라이드의 아이콘(선으로 그린 도형)이 거의
   보이지 않는다. 사용자에게는 "그룹 도형이 임포트되지 않는" 것처럼 보였으나, 실제로는
   그룹 평탄화와 custom geometry → SVG 변환은 정상 동작했다. 진짜 원인은 렌더 단계에서
   custom SVG의 선 두께가 도형 자체 좌표계(원본 EMU 단위)로 스케일되지 않아, 화면 크기로
   축소될 때 선이 사실상 소멸한 것이다. 면(fill)이 있는 도형만 남아 그룹 전체가 깨진 것처럼 보였다.

3. **차트 완전 실종** — 막대·도넛 차트가 통째로 사라진다. 0001은 차트를 "이미지로
   래스터화"하기로 했으나 실제 구현은 경고만 남기고 버렸다. 원본 차트 파트에는 데이터·
   유형·색상 참조가 그대로 남아 있어 벡터로 재현할 수 있다.

4. **본문 행간 과다로 세로 넘침** — placeholder에서 상속된 본문 텍스트의 줄 간격이
   원본보다 넓게 렌더돼 텍스트가 박스를 넘는다. 줄 간격이 도형에 직접 지정되지 않고
   레이아웃/마스터 스타일에 있을 때 이를 상속 해석하지 못해, 렌더러 기본 줄 높이가 적용된다.

실제 배포 덱을 재임포트해 슬라이드별로 검증하는 과정에서 **추가 네 가지 원인**이 더 드러났다.

5. **폰트 상속 오류로 제목/본문 줄바꿈 틀어짐** — 제목 placeholder의 run에 폰트가
   명시되지 않으면, 레이아웃/마스터 placeholder가 지정한 실제 폰트를 건너뛰고 곧장
   테마 major 폰트로 폴백한다. 테마 major가 굵은 변형(Heavy 등)이면 글자 폭이 달라져
   줄 수가 늘고, 인접 요소와 겹치거나 박스를 넘친다.

6. **투명(noFill) 차트를 색칠해 중복 렌더** — 원본이 차트 series를 noFill로 두고 실제
   시각 막대는 별도 도형(굵은 선 등)으로 그린 경우, 차트를 색칠해 그리면 진짜 막대와
   중복돼 어긋나 보인다.

7. **그라데이션 테두리/채움 누락** — 도형 테두리·채움이 그라데이션일 때 색 해석에
   실패해 테두리 없는 투명 박스로 렌더된다(콜아웃 박스·중앙 강조 박스가 사라짐).

8. **줄 간격이 문단 요소에 전파되지 않음** — 텍스트박스 컨테이너에만 줄 간격을 걸면,
   전역 스타일의 문단 기본 줄 높이가 이를 덮어써 실제 문단은 넓은 줄 높이로 렌더된다.
   (원인 4로 줄 간격을 올바로 추출해도, 렌더 단계에서 문단에 적용되지 않으면 무효)

## Decision

임포트 변환기를 원본 충실도 우선으로 정정한다. 네 가지 원인을 각각 근본 지점에서 고친다.

### 1. autofit 기본값을 "축소 없음"으로

임포트 경로에서 OOXML autofit 태그가 없으면 축소 모드가 아니라 "축소 없음"으로 해석한다.
이는 0001의 "임포트 시 autofit 비활성화" 결정을 실제로 관철하는 것이며, 명세상 기본값과도
일치한다. 명시적 autofit 태그(축소 없음/도형맞춤/정규화 스케일)가 있을 때의 처리는 유지한다.

### 2. custom SVG 선 두께를 도형 좌표계로 스케일

custom geometry 도형을 SVG로 렌더할 때, 선 두께를 도형의 원본 좌표계(viewBox) 기준으로
환산한다. 그래야 도형이 화면 크기로 축소·확대돼도 선이 원본과 같은 시각적 굵기로 보인다.
가로·세로 스케일이 다른 경우를 포함해 일관된 기준으로 환산한다.

### 3. 차트를 벡터(SVG)로 임포트 — 0001의 "래스터화" 결정 대체

차트 파트 XML을 파싱해 차트 프레임 위치·크기 안에 SVG 도형으로 재현한다. **주요 차트 유형을
포괄**한다: 세로/가로 막대, 꺾은선, 파이/도넛. 색상은 차트 색상 파트와 테마에서 해석한다.
축·범례·값 라벨은 원본에 근접한 수준으로 그린다. 지원하지 않는 유형(분산형·방사형 등)은
기존처럼 경고 후 건너뛰되, 유형별로 확장 가능한 분기 구조로 설계한다.

래스터화 대신 벡터를 택한 이유: 데이터가 원본에 온전히 남아 있어 재현이 가능하고, 벡터는
확대에도 선명하며, 임포트 후 편집·재내보내기 파이프라인과 자연스럽게 맞물린다.

### 4. 줄 간격 상속 해석

도형에 줄 간격이 직접 지정돼 있지 않으면 placeholder 상속 체인(레이아웃 → 마스터의
해당 스타일)을 순회해 줄 간격을 해석한다. 0001이 이미 폰트 크기·색상에 대해 도입한
상속 해석 방식을 줄 간격으로 확장하는 것이다.

### 5. 폰트명도 상속 체인에서 해석

폰트명 상속을 폰트 크기·색상과 동일한 우선순위로 처리한다: run 명시 → 레이아웃/마스터
placeholder 지정 폰트 → 테마 폰트 폴백. 상속 단계를 건너뛰고 곧장 테마 major로 가지 않는다.
테마 참조("+mj-lt" 등)는 폰트명으로 저장하지 않고 폴백에 맡긴다.

### 6. 투명 차트 렌더 생략

차트의 모든 series(및 데이터포인트)가 명시적 noFill이면, 실제 시각 요소는 별도 도형으로
그려져 있다고 보고 차트를 렌더하지 않는다. 채움이나 그라데이션이 하나라도 있으면 렌더한다.

### 7. 그라데이션 색을 첫 stop으로 근사

도형 테두리·채움이 그라데이션이면 첫 gradient stop 색을 단색으로 근사한다(원인 2의
custom SVG stroke 근사와 동일 전략). 테두리는 python-pptx의 line API 접근이 그라데이션을
단색으로 변형하는 부작용이 있으므로, API 접근 **전에** XML에서 추출한다.

### 8. 줄 간격을 문단 요소에 직접 적용

계산한 줄 간격을 컨테이너뿐 아니라 각 문단 요소에도 직접 적용해, 전역 문단 스타일이
이를 덮어쓰지 못하게 한다.

## Acceptance Criteria

- autofit 태그가 없는 임포트 텍스트가 원본 폰트 크기로 렌더된다(불필요한 축소 없음).
- 그룹 내 라인아트 아이콘의 선이 원본과 유사한 굵기로 보인다.
- 주요 유형의 차트가 임포트 후 벡터로 표시되며 데이터·색상이 원본과 근접한다.
- 상속된 줄 간격이 반영돼 본문 텍스트의 세로 넘침이 해소된다.
- 제목/본문 폰트가 레이아웃/마스터 지정 폰트로 상속돼 줄바꿈이 원본에 근접한다.
- 투명(noFill) 차트는 렌더하지 않아 실제 막대 도형과 중복되지 않는다.
- 그라데이션 테두리·채움 도형이 근사 단색으로 표시된다.
- 각 근본 원인마다 재현 → 수정 확인 회귀 테스트가 존재하고 전체 테스트가 통과한다.

## Out of Scope (알려진 잔여 차이)

- 원본 지정 폰트(예: 특정 브랜드 Display 폰트)가 렌더 환경에 미설치면 브라우저 폴백으로
  글자 폭이 달라져 줄바꿈이 원본과 다를 수 있다. 완전 일치는 폰트 임베딩(@font-face)이
  필요하며 별도 과제로 둔다.
- 그라데이션의 다중 stop·각도·경로는 단색 근사로 대체한다.
- 다이어그램의 직각 커넥터·일부 복합 custom geometry 아이콘의 세부 형태는 근사에 그칠 수 있다.

## Out of Scope

- 분산형·방사형 등 비주요 차트 유형의 벡터 재현.
- 차트 애니메이션·상호작용·정밀한 눈금 알고리즘 재현.
- 원본과의 픽셀 단위 완전 일치(디자인 스펙 스키마 표현 한계 내 최대 근접).

## Consequences

### Positive

- 0001이 표방한 "디자인 요소 최대 보존"을 실제 결과에서 관철.
- 그룹·아이콘·차트가 포함된 실무 덱의 임포트 충실도가 크게 향상.
- 차트가 편집 가능한 벡터로 남아 후속 수정/재내보내기와 호환.

### Negative / Risks

- 차트 벡터 재현은 유형별 렌더 로직이 필요해 코드 표면이 늘어난다.
- 원본 차트의 세밀한 스타일(그라디언트·그림자 등)은 근사에 그칠 수 있다.
