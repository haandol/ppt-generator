# HTML·PPTX 렌더 패리티 게이트

Date: 2026-07-23

## Status

Accepted (2026-07-23)

## Context

하나의 디자인 스펙은 HTML 미리보기와 편집 가능한 PPTX로 각각 변환된다. 두 출력은 같은
콘텐츠와 배치 의도를 표현해야 하지만, 렌더러별 테스트와 수정 흐름이 분리되어 있어 한쪽
출력의 충실도 수정이 다른 쪽에 누락될 수 있다. HTML에서 해결한 문단 간격·텍스트 배치가
PPTX에는 반영되지 않거나, PPTX 변환기의 기본 테마 효과가 HTML에는 없는 그림자를
추가하는 식의 드리프트가 실제 사용자 결과물에서 뒤늦게 발견된다.

두 출력은 브라우저와 Office라는 서로 다른 렌더링 엔진을 사용하므로 픽셀 단위 동일성을
항상 보장할 수는 없다. 그러나 위치·크기·텍스트·목록·간격·색상·선·효과 같은 디자인
스펙의 의미가 양쪽에 반영되는지는 결정론적으로 검증할 수 있다. 앞으로 한 렌더러를
수정할 때 다른 렌더러의 영향 검토를 개발자의 기억에만 맡기지 않는 하네스가 필요하다.

## Decision Drivers

- 디자인 스펙은 HTML과 PPTX 출력의 단일 소스이므로 공유 의미는 두 출력에서 보존되어야 한다.
- 한쪽 출력만 검사하는 단위 테스트는 다른 출력의 조용한 회귀를 탐지하지 못한다.
- 폰트 엔진과 Office 구현 차이 때문에 모든 환경에서 픽셀 비교를 필수화하면 테스트가
  불안정해진다.
- 브라우저 보안, iframe 컨테이너처럼 HTML에만 존재하는 동작은 정당한 예외로 남아야 한다.
- 새 렌더 필드가 추가될 때 패리티 검토 자체가 누락되는 경우도 자동으로 드러나야 한다.

## Decision

HTML과 PPTX를 하나의 렌더 패리티 계약으로 관리한다.

디자인 스펙의 렌더 관련 필드는 공유 의미, HTML 전용, PPTX 전용 또는 비시각 메타데이터로
분류한다. 분류되지 않은 새 필드는 테스트 실패로 처리해 개발자가 두 출력의 책임을
명시하게 한다. 공유 의미를 변경하면 동일한 디자인 스펙을 두 출력으로 변환하는 교차
렌더 회귀 테스트에서 HTML 표현과 PPTX 객체·문서 표현을 함께 검증해야 한다.

HTML 렌더 경로 또는 공유 렌더 계산을 변경할 때는 다음 중 하나를 반드시 남긴다.

- 양쪽 출력에 같은 의미가 적용됨을 보이는 교차 렌더 테스트와 필요한 PPTX 반영
- 브라우저 보안·문서 컨테이너 등 HTML 전용임을 설명하는 명시적 분류와 해당 출력 테스트

PPTX 경로를 변경할 때도 같은 규칙을 대칭으로 적용한다. 좌표, 줄바꿈, 자동 맞춤, 문단
간격, 목록, 도형 효과처럼 시각 결과가 렌더 엔진에 민감한 변경은 구조 검증에 더해 실제
HTML과 PPTX 렌더를 비교하는 시각 QA를 수행한다. 상시 테스트는 외부 Office 설치에
의존하지 않는 구조 검증으로 유지하고, 시각 QA는 고위험 변경과 원본 충실도 작업의
완료 조건으로 둔다.

에이전트 가이드와 테스트 체크리스트는 이 계약을 필수 검증 단계로 안내한다. 개별
렌더러 테스트만 추가하고 다른 출력의 영향 분석을 생략한 변경은 완료로 간주하지 않는다.

## 대안 검토

| 대안 | 판단 |
|---|---|
| 문서 체크리스트만 추가 | 실행 강제가 없어 기존과 같은 누락이 반복될 수 있으므로 제외 |
| 모든 변경에서 HTML·PPTX 픽셀 비교 강제 | 가장 직접적이지만 폰트·플랫폼·Office 렌더러 차이와 외부 도구 의존으로 상시 테스트가 불안정해 제외 |
| 두 렌더러를 하나의 구현으로 통합 | 출력 모델이 CSS/DOM과 OOXML로 근본적으로 달라 복잡성과 결합도가 커져 제외 |
| 필드 분류 + 구조 교차 테스트 + 고위험 시각 QA | 결정론적 상시 게이트와 실제 화면 검증을 결합하면서 정당한 출력별 차이를 유지할 수 있어 채택 |

## Consequences

### Positive

- HTML에서 수정된 공유 렌더 의미가 PPTX에 빠지는 회귀를 같은 변경에서 발견할 수 있다.
- 새 디자인 스펙 필드는 어느 출력의 책임인지 명시적으로 분류된다.
- 브라우저 전용 동작과 실제 패리티 결함을 구분해 불필요한 PPTX 변경을 피한다.
- 시각 QA가 필요한 고위험 변경의 기준이 명확해진다.

### Negative / Risks

- 공유 렌더 변경은 두 출력에 대한 테스트 작성이 필요해 변경 비용이 증가한다.
- 구조 검증만으로 폰트 대체나 렌더 엔진별 미세한 픽셀 차이를 모두 탐지할 수는 없다.
- 필드 분류가 지나치게 넓은 예외로 사용되지 않도록 리뷰가 필요하다.
- 시각 QA가 필요한 변경은 LibreOffice 또는 실제 PowerPoint가 있는 환경에서 별도 검증
  시간이 든다.

### 검증으로 확인된 사항

- 디자인 스펙에서 도달 가능한 모든 중첩 필드가 분류 대상이며, 새 필드나 새 중첩
  스키마가 분류되지 않으면 테스트가 실패한다.
- 출력 전용 또는 메타데이터 필드는 구체적인 비공유 사유가 없으면 테스트가 실패한다.
- 하나의 디자인 스펙으로 배경, 좌표, 크기, 패딩, 문단 간격, 행간, 불렛, 폰트,
  하이퍼링크, 도형, 선, 화살표, 효과를 HTML과 PPTX에서 함께 검증한다.
- 전체 테스트와 정적 검사가 통과해 기존 렌더·임포트 동작과의 회귀가 없음을 확인했다.
