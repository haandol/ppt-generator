# 작은 뱃지 도형의 텍스트는 PPTX 에서 줄바꿈하지 않는다

Date: 2026-06-16

## Status

Accepted (2026-06-16)

## Context

디자인 스펙은 번호 뱃지(예: 카드 좌상단의 "01"·"02") 를 작은 원형/사각 도형 안에 짧은 텍스트로 표현한다. HTML 미리보기에서는 이 텍스트가 한 줄로 잘 들어가는데, PPTX 로 내보내면 같은 도형 안에서 "0"과 "1"이 세로로 쪼개지는 줄바꿈이 발생한다.

원인은 두 렌더링 경로의 텍스트 박스 모델 차이다. PPTX 도형은 텍스트 프레임에 **기본 내부 여백(좌우 약 0.1인치씩)**이 있고, 작은 도형(수십 px 폭)에서는 이 여백이 가용 폭의 큰 비중을 먹는다. 거기에 도형 폭 대비 상대적으로 큰 글자가 들어가면 PowerPoint 의 자동 줄바꿈(word wrap)이 글자를 다음 줄로 흘린다. HTML 은 동일 상황에서 박스를 넘겨 그리므로(overflow) 줄바꿈이 눈에 띄지 않아, 미리보기·최종본 사이에 보이지 않던 차이가 PPTX 에서만 드러난다.

design/0001 은 디자인 스펙을 단일 소스로 HTML·PPTX 를 각각 결정론적으로 변환한다고 정했다. 그런데 "같은 스펙이 두 경로에서 시각적으로 같게 보인다"는 약속이, 도형 내부 텍스트 줄바꿈 처리의 비대칭 때문에 작은 뱃지에서 깨진다.

## Decision Drivers

- 디자인 스펙이 의도한 "한 도형 = 한 줄 라벨"(번호 뱃지)이 PPTX 에서도 그대로 보여야 한다 (design/0001 의 경로 간 일관성).
- 한 글자/두 글자짜리 짧은 라벨이 도형 안에서 쪼개지는 것은 명백한 시각 결함이다.
- 정상적으로 여러 줄이 필요한 본문 카드의 줄바꿈까지 막아서는 안 된다 — 줄바꿈 억제는 "줄바꿈이 의도가 아닌" 요소에 한정해야 한다.

## Decision

**짧은 라벨을 담은 컴팩트한 도형은 PPTX 변환 시 텍스트 자동 줄바꿈을 끄고, 내부 여백이 가용 폭을 잠식하지 않도록 처리한다.** 도형의 텍스트가 한 줄 라벨로 의도된 경우(작은 치수 + 짧은 단일 텍스트), word wrap 을 비활성화해 한 줄로 유지한다.

- 본문을 담는 일반 카드/텍스트 박스의 줄바꿈 동작은 그대로 둔다 — 여러 줄이 정상인 요소까지 한 줄로 강제하면 잘림이 생긴다. 줄바꿈 억제는 "줄바꿈이 결함인" 컴팩트 라벨 도형에만 적용한다.
- 도형이 텍스트보다 충분히 크도록 보장하는 책임은 디자인 스펙 생성(폰트/치수)에 있고, 본 결정은 export 단계에서 "스펙이 한 줄을 의도했으면 PPTX 도 한 줄로 낸다"를 보장하는 안전장치다.

## 대안 검토

| 대안 | 설명 | 채택하지 않은 이유 |
|---|---|---|
| 현행 유지 | PPTX 기본 word wrap 그대로 | 작은 뱃지에서 번호가 쪼개지는 결함 지속 |
| 모든 도형 word wrap 끔 | 도형 전체에 줄바꿈 비활성화 | 여러 줄이 정상인 본문 카드가 한 줄로 잘림. 과교정 |
| 생성 단계에서 뱃지 도형을 키우게만 강제 | 프롬프트로 도형 치수↑/폰트↓ 유도 | LLM 준수가 불확실하고, PPTX 내부 여백 변수를 생성기가 정확히 모름. export 단계 보장이 더 견고 |
| 뱃지 텍스트를 도형 밖 별도 텍스트박스로 | 번호를 도형과 분리 | sibling 겹침·정렬 문제를 새로 만들고, "도형 안의 번호"라는 디자인 의도를 바꿈 |
| **컴팩트 라벨 도형만 word wrap 끔 + 여백 정리** | 한 줄 의도 도형에 한정해 줄바꿈 억제 | **채택** — 결함만 제거하고 본문 줄바꿈은 보존 |

## Consequences

### Positive

- 번호 뱃지·짧은 라벨이 PPTX 에서도 한 줄로 나와 미리보기와 일치한다 (design/0001 경로 간 일관성 회복).
- 본문 카드의 정상 줄바꿈은 영향받지 않는다.

### Negative / Risks

- "컴팩트 라벨 도형"을 판별하는 기준(치수·텍스트 길이 임계)이 필요하다. 기준이 너무 넓으면 줄바꿈이 정상인 도형까지 한 줄로 눌러 텍스트가 도형을 넘쳐 보일 수 있다.
- word wrap 을 끈 도형은 텍스트가 길어지면 도형 밖으로 흘러넘친다 — 짧은 라벨 전제가 깨지는 입력(예상보다 긴 텍스트)에서는 오히려 넘침이 드러날 수 있다. 그 경우는 생성 단계 치수 책임으로 돌아간다.

### 검증으로 확인된 사항

- 컴팩트 판별은 "작은 치수 + 짧은 단일 라벨"의 교집합으로 한정한다 — 작은 도형이라도 텍스트가 길면(라벨이 아니면) 줄바꿈을 유지하고, 큰 카드는 길이와 무관하게 줄바꿈을 유지함을 확인. 과교정(본문 잘림)이 일어나지 않는다.
- 번호 뱃지 케이스(작은 원형 + "01"류 두 글자)에서 줄바꿈이 꺼지고 내부 여백이 0이 되어 한 줄로 유지됨을 단일 텍스트·문단(runs) 두 경로 모두에서 확인.
- 줄바꿈 억제 판별 기준(치수·글자 수 임계)은 코드 상수로 두어, 임계 조정이 ADR 변경 없이 가능하다.
