# 컨텍스트 안전 HTML 렌더링

Date: 2026-07-21

## Status

Accepted

## Context

HTML 미리보기는 사용자 입력, 임포트된 문서, 클라이언트 LLM 출력에서 온 텍스트,
하이퍼링크, 이미지 참조, 색상과 벡터 경로를 HTML 속성 및 CSS에 삽입한다. 일반 텍스트
이스케이프만으로는 따옴표가 포함된 속성값이나 위험한 URL scheme을 차단할 수 없다.
생성된 미리보기를 브라우저에서 열 때 입력값이 마크업이나 이벤트 속성으로 해석되면
프로젝트 내용을 넘어 브라우저 실행 컨텍스트에 영향을 줄 수 있다.

## Decision

HTML 렌더링은 출력 위치별로 다른 안전 규칙을 적용한다.

- 텍스트 노드는 HTML 텍스트 컨텍스트로 이스케이프한다.
- HTML 속성값은 따옴표를 포함해 속성 컨텍스트로 이스케이프한다.
- 하이퍼링크는 명시적으로 허용된 URL scheme만 클릭 가능한 링크로 만든다. 그 외 값은
  텍스트로 유지한다.
- 이미지 참조는 프로젝트 상대경로 또는 허용된 이미지 URL scheme만 렌더링한다.
- 색상, 정렬, 크기 같은 CSS 값은 자유 문자열을 그대로 삽입하지 않고 각 도메인의
  허용 형식으로 검증한다.
- 벡터 경로는 path data로만 취급하며 마크업을 삽입할 수 없다.

입력 신뢰 여부와 관계없이 같은 규칙을 적용한다. 생성 프로젝트와 임포트 프로젝트의
출력 정책을 나누지 않는다.

## Alternatives Considered

| 대안 | 판단 |
|---|---|
| 일반 텍스트만 escape | 속성·URL·CSS 컨텍스트를 보호하지 못해 제외 |
| 생성 프로젝트 입력은 신뢰 | 외부 콘텐츠와 LLM 출력이 섞이므로 신뢰 경계가 불명확해 제외 |
| 완성된 HTML 전체를 sanitizer로 후처리 | 레이아웃용 스타일과 SVG가 손실될 수 있어 제외 |
| 렌더 시점에 컨텍스트별 escape와 allowlist 적용 | 의도를 보존하면서 주입을 차단해 채택 |

## Consequences

### Positive

- 하이퍼링크, 이미지 참조, 벡터 경로를 통한 마크업·속성 주입을 차단한다.
- 안전 규칙이 렌더 경계에 모여 모든 생성 경로에 동일하게 적용된다.

### Negative / Risks

- 기존 문서에 포함된 비표준 URL scheme이나 자유 형식 CSS 값은 더 이상 그대로
  렌더링되지 않을 수 있다.
- 허용 형식이 늘어날 때 allowlist를 명시적으로 갱신해야 한다.

## Acceptance Criteria

- 따옴표와 이벤트 속성 형태의 입력이 마크업 구조를 바꾸지 않는다.
- 스크립트 실행이 가능한 URL scheme은 클릭 가능한 링크나 이미지로 출력되지 않는다.
- 정상적인 웹 링크, 메일 링크, 프로젝트 상대 이미지와 벡터 경로는 유지된다.
- 생성된 HTML의 기존 레이아웃과 텍스트 표현은 안전 처리 외에는 변하지 않는다.
