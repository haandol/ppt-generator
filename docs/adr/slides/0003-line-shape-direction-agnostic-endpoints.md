# line shape 방향 무관 끝점 계약

Date: 2026-07-21

## Status

Accepted (2026-07-21)

## Context

다이어그램의 화살표·연결선은 `line` 종류의 shape 로 표현되고, 다른 모든 shape 와 마찬가지로 `(left, top, width, height)` 사각형(bbox)으로 기술된다. 그런데 line 은 사각형을 채우는 게 아니라 사각형의 두 대각 꼭짓점을 잇는 선이라, bbox 의 부호(음수 width/height)가 선의 기울기 방향을 결정한다. 이 "부호가 방향을 뜻한다"는 규칙은 사각형 채움 shape 에는 없는 line 고유의 의미이고, 좌표를 만드는 쪽(클라이언트 LLM)과 렌더링하는 쪽이 이 의미를 정확히 같게 해석해야만 선이 두 노드에 붙는다.

문제는 이 계약이 어디에도 완결적으로 적히지 않아 반복적으로 어긋난다는 점이다. 위→아래로 내려가는 화살표는 양수 height 로 자연스럽게 표현되지만, 아래→위·오른쪽→왼쪽으로 향하는 화살표(back-edge, 대각선 연결)는 음수 성분을 써야 한다. 이때 `top`/`left` 가 "선의 시작점"인지 "bbox 의 최소 좌표 모서리"인지가 모호해서, 좌표를 만드는 쪽이 시작점을 넣으면 선 전체가 `|height|` 만큼 밀려 노드에서 떨어진 채 허공에 뜬다. 여러 화살표가 동시에 밀리면 서로 엇갈려 다이어그램이 읽히지 않는다.

## Decision Drivers

- line 의 bbox 부호는 방향(기울기)을 인코딩하며, 이 의미는 채움 shape 에는 없다 — 좌표 생성자와 렌더러가 반드시 동일하게 해석해야 한다.
- 좌표는 사람이 아니라 클라이언트 LLM 이 생성하며, 규칙이 프롬프트에 명시되지 않으면 방향별로 다른 실수를 반복한다.
- 화살표 끝점이 노드 변에 붙는지는 순수하게 렌더 결과로만 드러나는 시각 품질이라, 스펙 단계에서 놓치기 쉽다.
- 선의 끝점이 노드에 붙지 않는 결함은 렌더 실패가 아니라 "조용히 잘못된" 결과 — lint 가 사후에 잡아주지 않으면 그대로 배포된다.

## Decision

line shape 의 bbox 를 **방향 무관(direction-agnostic)** 으로 정의한다. bbox 는 항상 선이 지나는 두 끝점을 감싸는 사각형이며, `top`/`left` 는 그 사각형의 **최소 좌표 모서리**(위·왼쪽)를 뜻한다 — 선의 시작점이 아니다. 성분의 부호가 선의 기울기를 정한다: 양수 height 는 위→아래(↘), 음수 height 는 아래→위(↗)로 그려지되 두 경우 모두 bbox 는 `top ~ top+|height|` 범위를 차지한다. width 도 대칭으로 적용된다. 화살표 머리(`end_arrow`/`start_arrow`)는 흐름의 도착 노드 변에 놓는다.

렌더러는 이 계약을 신뢰하되, 방어적으로 음수 성분을 정규화해 어떤 방향 조합이든 두 끝점이 bbox 의 올바른 대각 꼭짓점에 오도록 한다 — 좌표 생성자가 부호를 틀리게 줘도 선이 노드 사이에 걸리도록. 스펙 생성 프롬프트(diagram_grid 의 화살표 좌표 규칙)에는 이 "부호=방향, top/left=최소 모서리" 계약과 방향별 예시를 명시해 클라이언트가 처음부터 맞는 좌표를 만들게 한다. 나아가 화살표 끝점이 어떤 노드 변에도 닿지 않으면 lint 경고로 승격해, 밀린 화살표가 시각 검증 없이도 드러나게 한다.

### 대안 검토

| 대안 | 설명 | 판단 |
|------|------|------|
| A. 계약 문서화 없이 좌표 예시만 늘림 | 프롬프트에 더 많은 화살표 예시를 넣어 패턴 학습에 기댐 | 부호의 의미가 명시되지 않아 새 방향 조합에서 다시 어긋남. 탈락 |
| B. 음수 성분 자체를 금지하고 항상 양수 bbox 강제 | line 도 채움 shape 처럼 최소 좌표에서 시작하는 양수 bbox 만 허용 | 대각선·back-edge 의 기울기 방향을 표현할 수단이 사라져 순환·역방향 다이어그램이 불가능해짐. 탈락 |
| **C. 방향 무관 계약 + 렌더러 정규화 + 프롬프트 명시 + lint 승격** | 부호는 방향으로 유지하되 의미를 한 곳에 못 박고, 렌더러가 방어, lint 가 사후 검출 | 표현력을 지키면서 생성·렌더·검증 세 지점에서 어긋남을 막음. 채택 |

## Consequences

### Positive

- 아래·왼쪽·대각선 등 모든 방향의 화살표가 좌표 부호와 무관하게 노드 변에 붙는다.
- 클라이언트 LLM 이 프롬프트의 명시적 계약을 따라 처음부터 맞는 좌표를 생성할 확률이 높아진다.
- 밀린 화살표가 lint 경고로 드러나, 시각 QA 를 돌리지 않아도 검출된다.
- 순환·back-edge 다이어그램의 기울기 표현력(음수 성분)을 그대로 유지한다.

### Negative

- 렌더러가 부호를 정규화하므로, "의도적으로 뒤집힌 bbox" 같은 극단적 표현은 정규화에 흡수되어 무시된다 — line 에는 그런 용례가 없어 실질 손실은 없다.
- 프롬프트에 계약과 예시가 추가되어 스펙 생성 프롬프트가 길어진다.
