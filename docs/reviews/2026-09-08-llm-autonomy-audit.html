확정된 요구사항 계약

필수 발표 골격

  • 총 4~20장
  • 1번은 title
  • 2번은 agenda content slide
  • 중간에 최소 1개의 Body content slide
  • 마지막은 closing

목적·시간·청중은 문맥 또는 기본값으로 보완하며 발표자 identity는 만들지 않는다.

사실 근거

  • 각 outline slide에 source_refs와 assumptions 저장
  • 출처 URL·KPI·외부 사실을 임의 생성하지 않음
  • 근거 없는 유용한 가정은 사실처럼 쓰지 않고 assumption으로 표시
  • Deck review가 unsupported claim을 별도로 보고

Title·Closing의 시각 자율성

  • title.main과 closing.message만 필수 역할
  • subtitle, presenter, action, contact는 선택·유일 역할
  • 역할은 배열 순서가 아니라 component_id로 식별
  • 고정 좌표·고정 문단 수·고정 divider 계약 제거
  • 모든 요소는 1280×720 캔버스 안에 있어야 함

5단 계층 단순화

  • LLM은 design_doc에 의미 ID·부모·역할·cell만 출력
  • 실제 좌표는 textbox/shape에 한 번만 출력
  • 서버가 component → group → section bbox를 자동 파생
  • 빈 design_doc, 누락된 component/grid 연결, 다중 leaf 연결은 거부
  • 의도 가능한 형제 영역 겹침은 error가 아닌 warning

AI Slop 방지 설계

DESIGN.md는 기존 세 영역에서 네 영역으로 확장됐다. AI Slop 방지 기준은 일회성 외부 스킬이 아니라 사람이 읽고 편집할 수 있는 프로젝트 디자인 의도의 정식 일부다.

GuardrailDESIGN.md가 기록하는 내용방지 대상
subject_specificity 실제 제품 UI, 데이터, 코드, 장소, 용어와 업무 artefact 주제와 무관한 stock metaphor와 generic icon
visual_hierarchy 주장·근거·보조 정보의 우선순위 모든 카드·배지·문구가 같은 크기로 경쟁하는 평면적 구성
layout_rhythm loud / breathe / turn / land의 덱 리듬 모든 장이 같은 밀도와 템플릿을 반복하는 단조로움
decoration_policy 데이터·그룹·위계·내비게이션·브랜드 기능이 있는 장식만 허용 기능 없는 gradient, glass, accent bar와 카드 장식
content_grounding 구체적 주장, 실제 예시, 출처와 명시적 가정 generic filler, KPI theater와 근거 없는 정량 표현
같은 content archetype은 사용자가 명시적으로 요구하지 않은 한 최대 2장까지만 연속 사용할 수 있다. Deck review는 3장 연속 반복을 duplicate_content 후보로 검사한다.

관련 구현: DESIGN.md draft prompt · DESIGN.md parser · optional art-direction skill

품질 검사와 수정 권한

Deck review

모든 슬라이드가 생성된 뒤 다음 덱 전체 문제를 한 번에 검사한다.

  • unsupported claim
  • narrative gap
  • duplicate content
  • terminology drift
  • agenda mismatch
  • conclusion mismatch
  • time density

리뷰는 read-only이며 high 의미 이슈만 사용자 결정을 요구한다.

Visual QA patch

전체 DesignSpec을 다시 생성하지 않고 검증된 이슈의 허용 필드만 교체한다.

  • 위치·크기·패딩·정렬·행간
  • autofit·글꼴 크기·색상
  • 검증된 layering 이슈의 z-index
  • contrast 이슈의 배경색

텍스트·데이터·요소 수·배열 순서·슬라이드 수는 patch할 수 없다.

Playwright를 사용할 수 없으면 클라이언트가 캡처한 PNG를 screenshot_path로 전달한다. 서버는 파일 존재 여부와 PNG header를 검증해 프로젝트 iteration 경로에 고정한다.

관련 구현: deck review service · Visual QA patch service · screenshot fallback and final export
